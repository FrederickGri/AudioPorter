# Contributing

Use the development instructions and run the tests before proposing changes.
Describe the concrete problem, resulting behavior, OS/CPU, and validation in a
pull request. Add a regression test when fixing a functional bug. Test native
packaging for changes to subprocess startup or dependency loading.

Use synthetic fixtures and public placeholder URLs. Never commit cookies,
private folder URLs, downloaded songs, personal paths, local settings, or raw
account logs. Review screenshots and error messages before posting an issue.

Contributions to original BiliSong code use the repository's MIT license.
